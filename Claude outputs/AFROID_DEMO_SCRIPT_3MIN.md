# AfroID — 3-Minute Live Demo Script

**Goal:** show the autonomous factory take an idea to running, reviewed code in one unbroken flow. Win the first 60 seconds. Never wait on a cold start in silence.

**Setup before you present (do NOT do these live):**
- Open the geezcodE IDE, already logged in, on the dashboard.
- **Pre-warm the orchestrator** 2–3 minutes before (it scales to zero): run one throwaway build or hit any `/v1/builder` endpoint so the first live action is instant. This is the single most important prep step.
- Have your idea text copied to clipboard so you paste, not type.
- Zoom the browser to ~110–125% so code and the streaming terminal are readable on a projector.
- Close every unrelated tab/panel; open only the IDE.

---

### 0:00–0:25 — The hook (say this while the dashboard is on screen)

> "This is AfroID. A founder types one sentence describing a startup. AfroID's agent swarm designs the architecture, writes the code across multiple files in parallel, validates it, and streams the whole build live — then works alongside you like a senior engineer. Watch it happen in real time, no cuts."

Keep it to two breaths. Don't explain the tech yet — show it.

### 0:25–0:50 — Idea in, zero questions

- Open the **Intake** modal. Paste a crisp, African-market idea, e.g.:
  > "A mobile-first savings-group (susu/chama) manager for informal cooperatives — members, contributions, payout rotation, and SMS reminders."
- Hit generate. As the **Architect blueprint** appears, narrate:
  > "No questionnaire. The Architect agent produced the full blueprint — stack, modules, data model, milestones — from that one line."
- Point at one concrete element (a data entity or milestone). Don't read the whole thing.

### 0:50–1:40 — Approve & Build (the centerpiece)

- Click **Approve & Build.** The terminal starts streaming immediately over WebSocket.
- Narrate over the stream (it's genuinely happening — let it carry you):
  > "This is a real parallel build. Each milestone is generated by Gemini, in parallel, not a template. Files land in the workspace as they're produced. That line is the AST validation pass — it's checking the generated Python actually parses."
- When it completes:
  > "Nine files, syntax-validated, written to the workspace — from one sentence, in under a minute."

*(If the stream is slow that day, keep talking about the architecture — the swarm, parallel milestones — until it catches up. Never go silent watching a spinner.)*

### 1:40–2:25 — The Copilot does coordinated multi-file work

- Open the generated `main.py`. In the Copilot dock, type:
  > "Add a GET /health/ready endpoint and a pytest test for it."
- When the diffs come back, narrate:
  > "One instruction, two coordinated edits — the endpoint and its test — queued for review. I approve the endpoint…" *(click approve; the amber '+1 more file queued' badge shows the test waiting)* "…and the test applies right after. That's real agentic multi-file editing, with a human in the loop on every change."

### 2:25–2:50 — Prove it runs

- Hit **Run Test Suite (pytest).** Let output stream to the terminal.
- If green: switch to the **Problems** panel — empty.
  > "Tests pass. Clean."
- *(Optional flourish if time: the Certify agent runs a compliance/RegTech check across jurisdictions — one click, shows AfroID isn't just codegen, it's a full company-formation factory.)*

### 2:50–3:00 — Land it

> "Idea to reviewed, tested, running code — one flow, no human writing boilerplate. That's the sovereign startup factory. Built entirely on Google Cloud and Gemini."

Stop. Don't add a fourth thing.

## Fallback plan (rehearse it)

- **Cold start / slow stream:** you pre-warmed, but if it lags, narrate the architecture (agent swarm, parallel milestones, durable build state, Cloud Tasks worker) until it catches up. The system is designed so a build survives instance scale-down — that itself is a good line: *"the build runs server-side and can't be lost, so I can keep talking."*
- **Copilot returns something odd:** have a second, known-good prompt ready ("add a GET /ping returning pong and its test") — the exact one validated in production.
- **A service hiccups:** the build path streams over WebSocket with an HTTP-polling fallback, so progress keeps flowing; say so and move on.
- **Total failure:** have a 45-second screen recording of the full flow as an emergency backup. Only use it if live is truly dead.

## What to have open in other tabs (for Q&A, not the demo)
- The GCP Cloud Run console showing the 12 services (proof it's real infra, not a laptop mock).
- The architecture diagram / this deck's system slide.

## The three lines that matter most
1. "From one sentence to running, tested code — watch, no cuts."
2. "Real parallel Gemini codegen, not templates — validated as it builds."
3. "Built natively on Google Cloud and Gemini."
